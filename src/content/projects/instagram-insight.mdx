## Overview

  caption="Page 1 of the pager: followers, 7-day reach and the latest posts, the glance-while-walking-past view the app is built around. All screenshots use a fictional account."
/>

A single-purpose Android app for a tablet mounted where my wife can glance
at her Instagram Creator account without opening Instagram and digging
through its Insights screens. It wakes on a double-tap, refreshes, and
auto-rotates through six pages: followers, growth, the latest post, totals,
audience and history graphs. It is kiosk-pinned, so nothing else on the
tablet is reachable.

It started with no backend at all, calling the Graph API directly and
refreshing its own token. It now reads everything from the
[Instagram Agent](/projects/instagram-agent/), which collects the data in
AWS, and shares its comment to-do list with the
[Instagram Dashboard](/projects/instagram-dashboard/) website.

## Problem

- **A passive, always-current view, not another app to open.** The point is
  a glance while walking past, not a session inside Instagram.
- **The tablet is not always plugged in.** Anything that runs in the
  background costs battery for updates nobody is looking at.
- **Meta's setup and docs don't match reality.** Getting comments to return
  anything needed a tester invite accepted by the account owner, a scope
  added later, and the app switched to Live mode, none of which errors when
  missing. `SETUP.md` in the repo has the full walkthrough.
- **Android kiosk behavior isn't obvious.** Screen Pinning, show-when-locked
  and turn-screen-on had to be combined by trial and error.
- **A device on a wall is a bad place for a write-scoped token.** A lost
  tablet leaked 60 days of full account access, with no way to revoke it
  short of redoing the consent flow.

## Approach

The app runs unattended on a device nobody is debugging, so every failure
has to degrade gracefully. A failed refresh never clears a good cache: the
dashboard always shows the last successful fetch rather than a blank
screen. Anything that is not guaranteed to work gets its own call and its
own try/catch, never batched with calls that are. And the refresh only runs
on wake, with two narrow, self-terminating background jobs as the only
exceptions.

<Phase
  id="dashboard-core"
  title="Dashboard and kiosk mode"
  status="done"
  goal="Get from a double-tap on a sleeping tablet to a current dashboard, with no lock screen and no background polling draining the battery."
  outcome="A double-tap wake lands on a six-page auto-rotating dashboard, refreshed on wake and cached for failures."
>

`refreshDashboard()` is the single entry point, called from `onResume()` on
every wake and cold launch. It writes to `DashboardCache`, and returns a
failure without ever deleting what is already cached.

Kiosk mode is three settings working together:

- `setShowWhenLocked(true)` and `setTurnScreenOn(true)` in `onCreate`, so
  the wake skips the lock screen.
- Android Screen Pinning, which does not survive a reboot, so an adb
  shortcut re-pins and relaunches the app.
- A token pushed over adb through `onNewIntent`, since a pinned, running
  activity never goes through `onCreate` again.

<Callout variant="lesson" title="One unsupported metric in a combined call zeroes out the whole response">
  Batching `reels_skip_rate` or `profile_activity` into the same `/insights`
  call as reach, saved and shares silently zeroed all of them. Each newer or
  estimated metric got its own call and its own try/catch, so one
  unsupported field could not take the rest down with it. The agent's poller
  now applies the same rule and remembers which metrics a post rejects.
</Callout>

</Phase>

<Phase
  id="follower-reach-history"
  title="Growth, history and audience"
  status="done"
  goal="Answer 'how are we growing' when Meta has no follower history and only exposes a post's current totals."
  outcome="Daily snapshots build follower and per-post history locally; reach and audience come from Meta."

Follower count has no historical API, so the app stored its own daily
snapshots (`FollowerHistoryCache`), and the same for each post
(`PostMetricsHistoryCache`). Reach does have a real time series, so it was
backfilled 30 days in one call. Those local snapshots are the only copy of
that history anywhere, which is why they were later exported and imported
into the agent.

Every write follows **write-then-report**: post to Instagram first, then
record the action with the agent only once Instagram confirms. A failed
Instagram call is safe to retry; a failed recording after a successful post
only retries the recording. Actions go to the same table the dashboard
website writes, so a comment handled on either one leaves both lists.

<Callout variant="warning" title="The comments endpoint needs the app in Live mode, not just a valid scope and tester">
  With a tester invite accepted and `instagram_business_manage_comments`
  granted, `GET /{media-id}/comments` still returned an empty `data: []`, no
  error, while the Meta app was in Development mode. Nothing in the endpoint
  docs mentions it. Switching the app to Live is what made comments come
  back.
</Callout>

</Phase>

<Phase
  id="agent-cutover"
  title="Cutover to the agent"
  status="done"
  goal="Stop calling Meta from the tablet: make refreshes faster and take the write-scoped Instagram token off a device mounted on a wall."
  outcome="A wake refresh went from ~30 Graph calls in 8.6s to 5 agent calls in 1.6s."
>

It happened in two steps, each small enough to roll back:

1. **Comments and moderation through the proxy.** The agent passes Meta's
   JSON through unchanged, so the tablet's comment threading (parent
   resolution, self-detection, deduplicating replies Meta returns twice)
   kept working untouched.
2. **Every metric from the agent.** Posts, post detail, followers, reach and
   audience come from its `/metrics` routes, mapped onto the existing UI
   models, so no screen changed.

| | Before | After |
|---|---|---|
| Requests per wake | ~30 to the Graph API | 5 to the agent |
| Refresh time | 8.6s | 1.6s warm |
| Metrics on screen | after the comment fetch (~25s) | before it starts |
| Instagram token | sent on every call, refreshed on-device | no longer sent or refreshed |

<Callout variant="decision" title="Freshness traded for speed">
  A figure is now as recent as the agent's last poll of that post: every 5
  minutes in its first 6 hours, slower as it ages. Reach stops at the last
  day Meta has finished counting. For a glance dashboard that is the right
  trade.
</Callout>

</Phase>

## Future improvements

- **Retire the Instagram token entirely.** It is no longer sent anywhere,
  but it still acts as the "is this tablet set up" check.
- **Survive a reboot without adb.** Screen Pinning has to be re-applied by
  hand after a restart; a device-owner kiosk would remove that step.
